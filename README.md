# CNKIDownload

> 当前发布版：**v1.1.0**（Python 版）　／　[命令速查.md](命令速查.md) · [使用说明.md](使用说明.md) · [SECURITY.md](SECURITY.md)

CNKIDownload 用你**自己已经登录好**的 Edge / Chrome 打开知网（CNKI）文献详情页，
批量整理出 PDF 下载标签页，并把下载到本地的 PDF 自动归集、按编号重命名、跟踪进度、
出一份对账报告。

**它不破解验证码，不绕过知网的访问控制，也不能让没有权限的文献变得可下载。**
它是**半自动**的：程序负责搜索、定位、开标签页、检测下载、归集与对账；
**最后一击「PDF下载」永远由人完成。**

**零第三方依赖**：只用 Python 标准库，连 WebSocket 和 CDP 协议都是自己实现的。
所以「装了 Python 就能跑」，不需要 `pip install` 任何东西。

## 为什么必须半自动

这是本项目最重要的设计决定，不是偷懒：

| 做法 | 结果 |
|---|---|
| 用脚本模拟点击「PDF下载」 | 知网的滑块验证码**必然触发**，一批也下不下来 |
| 由**真人**点击「PDF下载」 | 不触发验证码，正常下载 |

所以程序把重复劳动（一篇篇搜索、一篇篇开页面、一篇篇数文件、一篇篇对账）自动化了，
只把「点一下」留给用户。这样做既稳定，也不需要跟知网的反爬机制对抗。

## 怎么开始：两条路，选一条

### 路线 A：不想装任何东西 → 用现成的 exe

去本仓库的 **Releases** 页面下载 `CNKIDownload.exe`，把它和一个清单文件（`.xlsx` 等）
**放在同一个文件夹**里，然后**双击**它。

> 那个文件夹里**只放一个清单文件**；多放几个程序会列出来问你，不会替你猜。
> 自动识别只认 `.xlsx` / `.xlsm` / `.csv` / `.tsv` / `.json`，**不认 `.txt`**
> （纯文本清单和普通记事本文件无法区分，请显式传路径）。

首次运行会自动：找到清单 → 换成工作清单 → 以调试模式打开 Edge → 留 3 分钟让你登录知网 →
搜索所有文献的详情页 → 打开第一批 10 个标签页。你在浏览器里挨个点「PDF下载」，
关掉标签页，**再双击一次 exe** —— 它会归集新下载的 PDF 并打开下一批。重复直到完成。

> exe 不在仓库里（二进制不进 git）。它由 `build_exe.cmd` 从源码构建后挂到 Release 上。
> 想自己构建：`build_exe.cmd`（Windows）/ `./build_exe.sh`（macOS、Linux）。

### 路线 B：有 Python（或愿意装一个）→ 直接用源码

要求 **Python 3.10 或更高**，没有任何第三方依赖：

```powershell
python 3.CNKIDownload.py --out "D:\论文\中文文献" --limit 3
```

第一次运行会自己打开浏览器并留出登录时间。三篇跑通后去掉 `--limit 3` 全量跑。
详细步骤见 [使用说明.md](使用说明.md)。

> 不知道怎么确认 `python` 能不能用？见 [使用说明.md](使用说明.md) 开头的
> 「先确认 python 命令能用」一节 —— 那里把 Windows 上那个「假 python」的情形也讲清楚了。

## 主战场与已验证范围

- **主战场**：知网 `kns.cnki.net` 的期刊论文、学位论文详情页。
- 已实测跑通的规模：单批 129 篇，成功入库 124 篇（约 96%），
  全靠「开标签页 → 人工点 → `--next` 归集」这套循环完成。
- 未收录的 5 篇里，4 篇是知网检索不到匹配题录（原题录疑似抄录有出入），
  1 篇是打开后未检出下载文件 —— **都不是程序能力问题**，需要人工按刊名 + 年卷期检索。

## 日常工作流

```text
python 3.CNKIDownload.py --out "<PDF 目录>"    ← 首次：开浏览器 + 解析 URL + 开第 1 批
        ↓  （人工到浏览器里挨个点「PDF下载」，点完关掉标签页）
python 3.CNKIDownload.py --next                ← 归集新下载的 PDF + 重算进度 + 开下一批
        ↓  （重复上面两步，直到剩余为 0）
python 3.CNKIDownload.py --status              ← 随时离线看进度
python 3.CNKIDownload.py --status --report     ← 额外生成一份 Markdown 对账报告
```

`--out` 会被记进 `cnki-state/cnki_config.json`，之后跑 `--next` 不用重复写。

> 💡 **默认模式和 `--next` 做的事是一样的**：每次运行都会先归集新下载的 PDF、重算进度，
> 再开本批标签页。`--next` 只是把「我现在是在续跑」写清楚。
> 真正只做一件事的是 `--collect`（只归集不碰浏览器）和 `--status`（只看进度）。

## 输入和输出

**输入**支持 `.xlsx` / `.xlsm` / `.csv` / `.tsv` / `.txt` / `.json`。
`2.make_list.py` 用 `zipfile` + `xml.etree` 自己解析 xlsx，不需要 openpyxl / pandas。
按表头自动识别这些列名（中英文都认）：

| 字段 | 认得的表头 |
|---|---|
| 编号 | 序号 / 编号 / no / num |
| 标题 | 中文标题 / 标题 / 题名 / title ← **必需** |
| 作者 | 作者 / 第一作者 / author |
| 期刊 | 期刊 / 刊名 / 来源 / journal |
| 年份 | 年份 / 年 / year |
| 跳过 | 已下文件 / 已下载 / fulltext（非空则不进清单） |

只有标题的纯文本清单也能用：每行一条，行首的 `12.` / `12、` 会被当作编号。

从知网或文献管理软件导出的表也能直接喂进来 —— 交给 `2.make_list.py` 转换即可。

**输出**：

```text
<--out 目录>/                         ← PDF 入库目录
├── 1_城市轨道交通短期客流预测方法比较研究.pdf
├── 2_中小企业数字化转型的路径与绩效研究.pdf
├── ...
└── _重复副本/                        ← 同一篇被重复下载时的副本，只挪不删

cnki-state/                           ← 状态目录（默认在工具目录下）
├── cnki_list.json                    工作清单
├── cnki_detail_urls.json             详情页 URL 缓存（重跑不用重新搜）
├── cnki_dl_state.json                已完成编号
├── cnki_failed.json                  搜索失败的条目
├── cnki_batch_info.json              上一批的信息
├── cnki_config.json                  上次用过的目录与端口
└── cnki_report.md                    --report 生成的对账报告
```

入库文件名统一为 `<编号>_<标题>.pdf`，编号就是清单里的 `no`，可以直接和你的数据表关联。

## 进度是怎么判定的（不用信状态文件）

程序会核对有效 PDF 文件和完整题录，**不再只认编号或标题前 10 字**：

1. **入库文件**：新归集文件会在 `cnki_config.json` 的 `verifiedFiles` 中记录完整题录的标识及
   PDF 的 SHA-256。重跑时核对题录与文件内容，标题截断不会丢掉对应关系。
   没有记录的旧文件，仅在文件名含唯一完整标题时计入进度；旧截断文件保留并提示人工核验。
2. **系统下载目录里的原始文件**：比较标题及作者。清单只有标题时，使用绑定当前题录的
   已核验搜索缓存中的作者，仍支持 `标题_作者.pdf`，无需用户补填作者。
   已知作者后缀后的系统重复序号可以剥离，短标题也能匹配。知网文件名中间的省略号只有
   在保留足够长的标题两端、作者一致且候选唯一时才接受；同名或无法唯一对应的文件留在原处。

搜索也只接受完整标题一致的详情页；同名结果需要作者、年份等证据才能区分，否则标为
“未唯一核验，需人工检索”。旧版 URL 缓存和题录变化的条目会重新搜索。

**升级不会自动纠正以前下错或改错名称的正文。** 请人工核对旧文件，不要仅凭原编号确认身份。
`verifiedFiles` 属于工作状态，也会暴露文献对应关系，不要公开 `cnki-state/`。

## 常见问题速查

| 现象 | 真正原因 | 怎么办 |
|---|---|---|
| **下完了，但 `cnki-out\` 里是空的** | 点「PDF下载」时文件落进了**系统下载目录**，还没被归集 —— **这是正常的** | 跑一次 `--next`（或再双击一次 exe），它会搬进 `cnki-out\` 并重命名 |
| 提示「端口在监听，但响应不是 DevTools 服务」 | 浏览器被关掉了，或系统代理拦了回环地址 | 重跑一次；本工具已自动给回环地址加了 `NO_PROXY` |
| 提示「浏览器已启动但端口没响应」 | 端口被别的程序占了 | 换 `--port 9223` |
| 打开的是知网首页而不是详情页 | 详情页 URL 抓错了 | 删掉 `cnki-state/cnki_detail_urls.json`，加 `--force` 重搜 |
| 某篇一直搜不到 | 题录与知网收录标题不一致 | 用 `--manual` 排除它，人工按刊名 + 年卷期检索 |
| 有文件下到了却没被归集 | 修改时间超过 6 小时 | 确认是这次的，加 `--any-age` 归集 |
| 归集后下载目录里还剩一份 | 同一篇重复下载 | 正常，副本在 `_重复副本/`，只挪不删 |
| 提示「需要人工验证」 | 触发知网滑块 | 到浏览器窗口滑一下，程序等 30 秒后重试 |
| 终端里中文乱码 | 控制台代码页不是 UTF-8 | 本工具已尽量自动切 UTF-8；仍乱码就用 Windows Terminal |

完整排查、参数逐条说明、限流处理、技术原理见 **[使用说明.md](使用说明.md)**。

## 隐私与安全

- 调试用的浏览器 profile 在用户数据目录（`%LOCALAPPDATA%\CNKIDownload\browser-profile`），
  里面有 Cookie 和机构登录态。**不要**提交到 GitHub、打包或发给别人。
- 工作清单和 `cnki-state/` 里的文件会暴露你的研究课题、文献题目和进度，`.gitignore` 已默认排除。
- 程序不读取、不导出 Cookie 内容；日志只打印标题、编号和本地路径。
- CDP 端口只绑定 `127.0.0.1`，启动前会检查端口是否空闲（被占用则报错，不硬上）。
- `4.ClearProfile.py` 默认只清缓存、保留登录态；`--all` 才会删整个 profile，
  且拒绝在磁盘根目录、用户主目录、系统个人文件夹等危险路径上执行。

安全问题与敏感信息处理见 [SECURITY.md](SECURITY.md)。

## 附：为什么是纯标准库

`CNKIDownload_cdp.py` 里那份 WebSocket 客户端（RFC 6455 握手 + 掩码分帧 + ping/pong）
和 CDP 调用封装，一共两百多行，替换掉了 `playwright` / `selenium` / `websocket-client`
三个依赖。代价是代码多了一点，换来的是：

- 用户**不需要** `pip install`，不用担心公司/学校网络装不上包；
- 能**冻成单文件 exe**，给完全不想碰命令行的同学；
- 不会有「驱动版本和浏览器版本对不上」这类经典故障
  （实测 Selenium 4.48 + msedgedriver 154 在 Edge 154 上所有命令直接抛空异常，整套不可用）。

思路与 SCIDownload 项目保持一致 —— 两个工具用同一套依赖模型，用户看一份说明就懂两个。
